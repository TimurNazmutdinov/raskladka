# Раскладка

Расчёт питания для походов: продукты, меню по дням, закупки и рюкзаки. Открывается двойным щелчком по `Раскладка.html` в Chrome или Edge (Windows). Сервер и установка не нужны. Данные (походы, наборы продуктов и блюд, планы) хранятся в браузере. Онлайн-версия: https://timurnazmutdinov.github.io/raskladka/

## Что умеет
- **Два типа расчёта** (экран «Поход»):
  - **Простой выезд** — число людей, число дней и цель по калориям (ккал/чел/день), особенности питания и заметки текстом. Маршрут, погода, пол, вес, километры и набор высоты не нужны и в расчёте не учитываются.
  - **Полноценный поход** — дни (вручную или из GPX-трека), погода и условия, каждый участник со своим весом, ростом, возрастом и аппетитом, снаряжение, заброски. Потребность считается по маршруту (формула Пандольфа), температуре и высоте. Можно задать и свою цель по калориям: тогда данные по дням необязательны.
- **Параметры расчёта** в Настройках разделены так же: «Простой выезд» (раскладка, меню, топливо и вода) и «Подробный расчёт» (ходьба, покрытие, сутки, высота).
- **Приёмы пищи.** По умолчанию завтрак, перекус, обед, перекус, ужин (доли 25/10/25/10/30). Приёмы можно добавлять, удалять, менять местами и переименовывать («Питание и заброски»).
- **Меню.** Генератор собирает меню из выбранных наборов продуктов и блюд; можно закрепить, заменить или убрать блюдо. Порции подгоняются под цель в пределах «мин / макс» каждого продукта. Если одного блюда не хватает до нужных калорий, приём собирается из нескольких блюд (до трёх) того же типа. Цель выше разумного предела (5500 ккал, Настройки → Меню) не раздувает порции. Минимумы приёмов не урезаются: если день вышел за цель, в предупреждениях написан перебор, а если меню не дотягивает до цели — недобор и причина (например, каких продуктов не хватает в наборе).
- **Сводка расчёта** (вкладка «Расчёт»): показатели, проверки и закупка по категориям; выгрузка в Excel и текстом.
- **Покупки.** Список, фасовка, рюкзаки, топливо, экспорт. Вкладка «Закупщики»: несколько закупщиков, назначение по отделам и продуктам, лист каждого закупщика.
- **Загрузка из файла** (`.xlsx`, `.csv`, `.json`): продукты, блюда и меню-план. Окно предпросмотра, пересчёт единиц по выбору (кг, штуки, «на группу»), связи названий, «Отменить последнюю загрузку». Файлы `.xls` сначала сохраните как `.xlsx`.

## Перенос на другой компьютер
Данные лежат в браузере, а не в папке с программой. Папку с файлами переносить можно, но походы и наборы нужно перенести отдельно: на старом компьютере «Настройки» → «Резервная копия» → «Сохранить копию (JSON)», на новом — «Настройки» → «Резервная копия» → «Восстановить из файла».

## Загрузка данных: простой шаблон
Кнопка «Скачать пустую форму» (или файл `Шаблон раскладки/Форма_для_загрузки_пустая.xlsx`): две вкладки — «Продукты» и «Блюда». Заполните обе или только одну: загрузить можно что-то одно. Подсказка «Как заполнить шаблон» — в окне загрузки. Колонка без заголовка в «Блюдах» читается как описание блюда (приложение сообщает об этом в предпросмотре). Меню-план (лист «План») тоже понимается, но в шаблон не входит.

## Файлы
- `Раскладка.html` — файл запуска; `index.html` только перенаправляет на него (нужно для ссылки на GitHub Pages).
- `styles.css`, `app.bundle.js`, `lib/` — всё, что нужно для работы. Папку можно переносить на другой компьютер целиком.
- `src/` — исходный код. После правки: `node tools/build.mjs` (пересобирает `app.bundle.js`). Только для разработки.
- `lib/` — `jszip.min.js` и шаблон Excel в виде `template.js`. Обновить шаблон: положить новый .xlsx в «Шаблон раскладки» и запустить `tools/update-template.ps1` (правый щелчок → «Выполнить с помощью PowerShell»).
- `tests/` — тесты, запуск `node tests/<имя>.mjs`; отчёт по встроенным блюдам: `node tests/report_dishes.mjs`.
- `tools/` — сборка и служебные скрипты (`make_blank_form.mjs` создаёт пустой шаблон загрузки).
- `pwa-off/` — отключённые `sw.js` и `manifest.json`. Корневой `sw.js` — воркер, который удаляет себя и очищает кэш у тех, кто ставил версию v1.
- `Шаблон раскладки/` — шаблон Excel и пустая форма загрузки. Сторонние данные для сверки лежат там же, но в репозиторий не попадают.
- `QUESTIONS.md` — решения, принятые без вопросов. `TZ_raskladka.md`, `PROMPT_v2/v3` — история задания.
